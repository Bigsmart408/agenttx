\title{\Large \bf \system: Causal Effect Transactions for Long-Running Coding Agents}
\author{Anonymous submission}
\maketitle

\begin{abstract}
Coding agents execute long trajectories in which later tool calls consume
filesystem state produced by earlier exploration, editing, compilation, and
testing.  Existing command, session, and checkpoint mechanisms either expose
unvalidated effects or discard later work that is independent of a failed
step.  We introduce Agent Effect Transactions (\aet), which use causal
dependencies among versioned filesystem effects as the recovery unit within
one opaque trajectory.  \system realizes \aet by capturing typed effects,
building a causal ledger, reconstructing affected object versions, and durably
publishing an approved frontier.  Across 144 controlled runs, \system retained
100\% of independent work and removed 100\% of invalid descendants; temporal
recovery retained 41\% at 64 calls.  At 48 document entries, retained artifacts
avoided 1,425 replay tokens versus temporal recovery and 3,340 versus
whole-session abort.  In 50 fresh x86 repeats of a ten-write comparison, the
full path measured 58.757~ms/step mean (68.169~ms/step p99) and was the only
policy with 50/50 causal-correct recoveries.
\end{abstract}

\section{Introduction}

Coding agents increasingly execute long, stateful software-engineering tasks
rather than produce a patch in one turn.  Their control loops interleave model
reasoning with tool actions and observations, allowing a plan to change after a
command fails or reveals new repository evidence~\cite{react}.  SWE-agent and
OpenHands expose repository navigation, file editing, shell commands, and tests
to the model~\cite{sweagent,openhands}.  SWE-bench likewise evaluates issue
resolution as an interactive process that can span several files and test
runs~\cite{swebench}.

We call such an execution a \emph{multi-step agent task} when each tool call can
consume observations or workspace state produced by earlier calls.  The agent
sees one adaptive trajectory, but the kernel sees process trees whose
filesystem effects become visible as they execute.  A late test may consume an
artifact from an earlier failed attempt, while an independent edit made between
them remains valid.  Recovery must keep effects provisional without forcing the
agent to replay the entire trajectory.

Existing systems preserve intermediate state at other boundaries.  Branch and
checkpoint runtimes retain a branch, session, or temporal prefix
~\cite{branchfs,waypoint,deltabox}.  \trycmd stages one opaque command in an
unprivileged semisolate and applies selected effects after approval
~\cite{try-osdi26}.  Agent-facing filesystems, process checkpointing, and
transactional filesystems target workspace control, full-session restart, or
ACID publication~\cite{yolofs,criu,dmtcp,valor,txfs}.  These recovery units do
not select a failed causal subgraph inside one opaque trajectory.

Consider four interleaved steps.  Step $s_0$ writes a faulty formatter, $s_1$
reads it and produces a report, $s_2$ edits an independent document, and $s_3$
tests the faulty output.  Recovery should remove $\{s_0,s_1,s_3\}$ while
retaining $s_2$.  No temporal checkpoint necessarily represents that state: a
suffix rollback also loses $s_2$, while a ledger without read evidence can keep
the invalid report.

This recovery-unit mismatch creates three systems challenges.  \emph{Dependency
discovery} must recover producer and consumer relations hidden by shells,
compilers, tests, and third-party programs.  \emph{Object identity} must
distinguish shared objects from names split by copy-up or replacement across
symlinks, hard links, renames, and bind mounts.  \emph{Selective
reconstruction} must rebuild a non-contiguous state despite repeated writes,
deletes, retained suffixes, and interrupted publication.

Existing substrates index provisional state by command, namespace, time, or
pathname, while failures propagate through dependencies among versioned
effects.  We therefore introduce Agent Effect Transactions (\aet), which use
the trajectory as the speculation unit and a causal effect subgraph as the
recovery unit.  \system realizes \aet on Linux by capturing READ, NEGATIVE,
WRITE, and DELETE effects, maintaining a causal ledger, and reconstructing
affected object versions.  An approval frontier and write-ahead log protect
publication, while persistent workers and incremental snapshots reduce repeated
execution cost.

Across 144 controlled runs, causal rollback retained 100\% of independent work
and removed 100\% of invalid descendants.  At 64 calls, temporal recovery
retained 41\% of independent work.  At 48 document entries, causal retention
avoided 1,425 replay tokens versus temporal recovery and 3,340 versus
whole-session abort.  These token results measure recovery-induced replay, not
total session-token savings.

This paper makes four contributions:
\begin{itemize}
  \item We formulate causal-subgraph recovery for opaque coding-agent
        filesystems, preserving independent work that follows a failed step.

  \item We introduce \aet, which represents filesystem effects and their causal
        dependencies as the basis for selective recovery.

  \item We build \system to realize \aet with object-aware reconstruction,
        fail-closed alias handling, durable publication, and efficient
        persistent execution.

  \item We evaluate \system through controlled recovery, latency, replay-token,
        failure-recovery, identity, and concurrency experiments.
\end{itemize}

\section{Background and Motivation}
\label{sec:background}

\subsection{Problem Setting and Recovery Units}

We model a coding-agent trajectory as an ordered sequence of tool calls
$T=\langle s_0,s_1,\ldots,s_n\rangle$.  A step may invoke a shell, compiler,
test runner, package manager, or arbitrary third-party program.  Descendant
processes can expose effects immediately, and later calls consume the
accumulated state.  A failed step can leave files, caches, deletions, or
diagnostics that affect later execution.

We classify effects as successful reads ($R$), negative lookups ($N$), writes
($W$), and deletes ($D$).  A negative lookup matters when a later write creates
the missing path, while directory ancestry affects how that path resolves.
Recording only writes misses derived artifacts; treating every touched path as
dependent discards independent work.  Exit status and temporal order therefore
do not identify the correct recovery set.

Paths are not stable object identifiers.  Symlinks, hard links, renames, and
bind mounts create aliases, while OverlayFS copy-up can split an inode during a
write~\cite{overlayfs}.  Recovery must track namespace, object identity, and the
version at which each effect was observed.

Isolation and recovery are different boundaries.  A per-call sandbox keeps the
host clean but repeatedly reconstructs state; a session sandbox amortizes setup
but normally aborts the whole trajectory; and a temporal checkpoint discards a
suffix.  None selects a failed producer and its non-contiguous descendants
while retaining independent later work.  Table~\ref{tab:granularity} makes
these native units explicit; checkpoint and whole-session rows describe
semantics rather than external-system executions.

Semisolates stage commands~\cite{try-osdi26}; agent-oriented filesystems and
branch runtimes manage workspaces or branches~\cite{yolofs,branchfs}; checkpoint
systems preserve complete process or session state
~\cite{waypoint,deltabox,criu,dmtcp}; and transactional filesystems protect ACID
publication~\cite{valor,txfs}.  Their native units remain commands, sessions,
branches, checkpoints, or explicit transactions.

Our target is a continuous speculative view that leaves the host unchanged
until approval, removes a failed effect and its descendants selectively, and
publishes the approved frontier durably.  We consider workspace-local effects
from trusted but fallible coding agents.  Network and cloud effects, process
memory, terminal state, and adversarial confinement remain outside scope.

\subsection{Analyzing the Execution Path}

\paragraph{Methodology.}
We run a deterministic 64-call coding workload under six modes.  The workload
contains repository exploration, a multi-file refactor, an injected failing CI
path, a report derived from the faulty file, independent documentation and
configuration edits, and a repair suffix.  We measure end-to-end wall time per
tool call, host cleanliness before approval, and the p50/p95 tails.  The full
comparison appears later in Table~\ref{tab:runtime}; the motivation matrix is
deliberately not an unsafe-versus-safe comparison alone, because bare execution
is not correctness-equivalent.

\paragraph{Observation.}
Bare execution is the latency lower bound at 49.7 ms/step but immediately
pollutes the host.  Per-call \trycmd costs 260.7 ms/step, shared \trycmd costs
254.0 ms/step, and the shared-checkpoint component costs 63.5 ms/step.
Full \system costs 148.5 ms/step while keeping the host clean; disabling read
tracing lowers it to 62.6 ms/step but loses read-derived dependencies.  Thus
the full traced path is 2.99$\times$ bare and per-call isolation is 5.24$\times$
bare, even before model/network latency is included.  Longer runs amortize
fixed setup (156.4, 139.5, and 107.0 ms/step at 54, 64, and 96 calls), but
the tail remains large: step p50 ranges from 19.6 to 24.4 ms, versus p95 from
684.8 to 724.0 ms.

\subsection{Analyzing the Recovery Path}

\paragraph{Methodology.}
We execute real filesystem effect DAGs rather than simulated graph nodes.  The
sweep varies trajectory length (16/32/64), shape (chain, fan-out, layered),
fault position (10/50/75\%), and independent-work ratio (25/50/75\%).  Causal,
temporal, and whole-session policies receive the same trajectory, while a
fourth mode removes read dependencies.  Three repeats yield 144 real-overlay
runs over 48 configurations, and every run checks both the speculative view
and the physical host before commit.

\paragraph{Observation.}
Full causal rollback retains 100\% of independent work and removes 100\% of
invalid descendants.  Temporal rollback removes invalid work but retains only
41\% of independent work at 64 calls; whole-session abort retains 0\%.
The no-dependency ablation retains apparent files but removes only 4\% of
invalid work.  In the long workload, the fault roots are
steps $[27,29,30]$; full tracing finds all three and removes the derived report,
whereas no-trace finds only step $27$ and leaves that report behind.

\paragraph{Implication.}
The temporal policy loses 59\% of independent work before any model is asked to
repair it.  In the token experiment, this corresponds to 1,424.7 avoided
replay tokens against an optimistic temporal checkpoint and 3,340.3 against
whole-session abort at 48 document entries.  These are recovery-induced replay
tokens, not total session-token savings.  The result is a semantic gap, not a
constant-factor implementation cost: faster isolation cannot compensate for
discarding work that was already correct.

\subsection{Design Requirements}

The measurements rule out four shortcuts.  Rebuilding isolation per call costs
5.24$\times$ bare execution and fragments trajectory state.  Shared temporal
state reduces setup cost but still discards independent edits, while disabling
read tracing misses compiler and test dependencies.  Path-only tracking also
remains insufficient: the tested hard-link cases pass, but bind mounts,
external aliases, and arbitrary generation changes fail closed.  The WAL
recovers interrupted publication but does not provide external all-path atomic
visibility.

Existing substrates index provisional state by command, namespace, time, or
pathname, while failures propagate through causal dependencies among versioned
effects.  The trajectory must therefore be the speculation unit, and the causal
subgraph must be the recovery unit.  Dependency capture, versioned object
identity, and selective reconstruction must work together.  A precise rollback
policy over an incomplete graph or unsupported identity relation is unsafe.

\section{Agent Effect Transactions}

\subsection{Model and Goals}

An Agent Effect Transaction is a tuple $\langle V,L,H,F\rangle$.  $V$ is the
current speculative filesystem view.  $L$ records tool steps and their effects,
while $H$ provides historical states needed for reconstruction.  $F$ separates
finalized steps from the speculative suffix.  A tool call reads and mutates $V$,
appends one node to $L$, and leaves the host unchanged.

The four components map directly to the goals in Section~2.  $V$ preserves
continuous cross-call state while isolating the host.  $L$ identifies a causal
recovery set, and $H$ reconstructs it without discarding an independent suffix.
$F$ publishes only approved effects.  AET defines these transitions without
requiring a particular tracing, snapshot, or commit implementation.

An AET exposes three transitions.
\emph{Append} executes one tool call in $V$ and adds its effects to $L$.
\emph{Recover} selects a failed node, computes its descendant closure, and
reconstructs the affected portion of $V$ from $H$.  \emph{Finalize} advances
$F$ and publishes only the approved versions.  These transitions obey three
invariants: the host is unchanged before finalization; successful recovery
removes every selected effect while preserving every non-overlapping retained
effect; and finalized steps never become speculative again.  The invariants
clarify the contribution boundary: AET specifies what must hold, while AgentTX
supplies one Linux implementation.

\subsection{Effect DAG}

Each ledger node $s_i=(i,\mathrm{tool}_i,E_i,P_i,\mathrm{status}_i)$ contains
effects and parent step identifiers.  Let $\mathrm{overlap}(p,q)$ hold when two
effect names identify overlapping objects.  For an active earlier step $j<i$,
the transaction adds $j\in P_i$ when:
\begin{itemize}
  \item $s_j$ writes or deletes $p$, and $s_i$ reads, negatively looks up,
        writes, or deletes an overlapping $q$.
  \item $s_j$ negatively looks up $p$, and $s_i$ later writes an overlapping $q$.
\end{itemize}
The first rule captures read-after-write and write serialization.  The second
captures assumptions based on absence.  The identity relation is part of the
AET contract; Section~4 states how AgentTX approximates it.

We make identity explicit with an abstract relation $\equiv_{\mathcal I}$ over
effect names.  Path equality implies overlap, but aliases may also overlap when
the relation can justify it.  A read through a file descriptor is attached to
the object opened earlier when the observation layer supplies that association;
otherwise the effect is unknown rather than guessed.  This separation prevents
the ledger from silently turning incomplete observation into a false dependency.

For a failed active step $f$, let $C_0=\{f\}$.  We compute
\begin{equation}
  C_{k+1}=C_k\cup\{s_i\mid P_i\cap C_k\neq\emptyset\},
  \qquad C(f)=\bigcup_{k\geq 0}C_k .
\end{equation}
$C(f)$ is the least transitive descendant closure among active, uncommitted
steps.  Temporal rollback instead selects the suffix $\{s_i\mid i\ge f\}$.

\subsection{Selective Reconstruction}

Let $W(C)$ contain paths written or deleted by steps in $C(f)$.  For each
target, the runtime obtains a state that predates its earliest selected effect.
It then checks every retained active effect against $W(C)$.  If a retained
effect overlaps a target, the runtime rejects recovery rather than guessing a
merge.  This fail-closed rule trades availability for a safety invariant:

\begin{quote}
After a successful causal rollback, no effect written by $C(f)$ is visible, and
every non-overlapping retained effect remains visible in the speculative view.
\end{quote}

The transaction marks selected nodes rolled back only after reconstruction
succeeds.  Historical states for invalidated steps can then be reclaimed.

\subsection{Commit Frontier}

The frontier $F$ is the largest finalized step identifier.  Every step at or
below $F$ is approved for publication or durably marked rolled back.  Advancing
to $F'>F$ publishes active write/delete effects in $(F,F']$ and leaves later
steps speculative.  Rolled-back holes therefore do not block monotonic
progress.

Publication and speculative recovery are separate transitions.  An
implementation must publish the frontier version even if a later speculative
step rewrites the same object.  AET requires durable recovery of that
transition, but not atomic multi-path visibility to external observers.

\section{AgentTX Design and Implementation}

\subsection{Tool-Boundary Effect Capture}

Writes and deletes are obtained by fingerprinting the unmounted upper layer
before and after a command.  Fingerprints include content and metadata, thereby
capturing repeated chmod, chown, touch, empty-directory, symlink, and whiteout
effects.  Linux OverlayFS may encode deletions as character-device or
\texttt{.wh.*} whiteouts; both forms are normalized to $D$ effects.

AgentTX captures successful reads and ENOENT/ENOTDIR lookups with
\texttt{strace}~\cite{strace}.  The parser follows process creation, tracks
working directories, and resolves modeled path operations relative to file
descriptors.  It records requested and resolved paths when a symlink changes
the name.  A failed trace invocation or parse aborts the step unless tracing is
explicitly disabled.  Coverage remains limited to modeled Linux pathname
syscalls; it does not prove that every filesystem access is observed.  Trusted
tools may declare effects directly, making their declarations part of the
trusted computing base.

An optional persistent eBPF backend emits the same effect contract from syscall
tracepoints and uses the same parser semantics.  The main evaluation uses
\texttt{strace}, whose coverage and latency were more stable on our host; the
backend choice does not change the AET contract.  For a relative path through a
non-\texttt{AT\_FDCWD} descriptor, either backend requires a resolved descriptor
origin; if the tracer cannot provide one, the tool call fails closed instead of
treating the caller's working directory as that origin.

The capture contract distinguishes three cases.  A path-based open or negative
lookup contributes a directly named $R$ or $N$ effect.  A descriptor-relative
operation contributes an effect only when the trace contains a resolvable
descriptor origin; inherited or duplicated descriptors without such an origin
remain outside the supported identity contract.  A trusted declaration can
fill this gap for a structured tool, but the declaration is an assumption, not
an independently verified observation.  This fail-closed boundary keeps the
causal ledger conservative instead of fabricating edges from command text.

\subsection{Shared Semisolate and Persistent Worker}

All calls in one session reuse a \trycmd \texttt{-N} upper layer.  This shared
layer provides the continuous speculative view required by AET.  Later commands
observe earlier uncommitted effects while the host remains unchanged.  The
launcher synchronizes \texttt{\$PWD} with the protected workspace because a
changed subprocess cwd alone can leave the environment inconsistent.

The persistent Python worker is a performance optimization over that design.
It exchanges length-prefixed requests inside one semisolate to amortize
namespace and overlay setup.  If the worker dies, the current request uses the
one-shot path; the following request starts a new worker.  This fallback
preserves availability without making worker reuse part of AET correctness.

\subsection{Snapshots and Aliases}

Before step $i$, the layer store records \texttt{before\_i}.  Regular files are
stored as immutable content-addressed blobs and hard-linked into snapshots.
After the first step, an incremental snapshot clones the prior tree and replays
only paths changed by the previous call.  Native whiteouts and mode-000 trees
are preserved.  Causal rollback restores only selected logical paths; temporal
rollback swaps the full upper tree to one pre-step image.

AgentTX treats ancestor-related paths as overlapping and records lexical and
resolved paths for supported symlink accesses.  Renames appear as path-level
delete/create effects; the session catalog supplies stable object identifiers
for known hard-link groups, but not for all namespace changes.  Bind-mount
equivalence is outside the identity model.

The supported identity levels are therefore deliberately ordered.  Directory
ancestors are conservatively overlapping, symlink accesses retain both names,
and rename is represented as a delete/create pair.  Hard-link relations are
promoted only when the substrate or the upperdir materializer verifies the
object identity; bind-mount relations remain fail-closed.  This policy may
reject a recovery that could be safe, but it avoids claiming precision that
path-level evidence cannot provide.

The active OverlayFS path enables \texttt{index=on}, preserving hard-link
visibility during live copy-up.  After one name is written, an in-transaction
read through its sibling observes the new bytes.  Before publication, AgentTX
discovers complete host-visible alias groups and expands both frontier and
retained-suffix checks.  It updates the linked host inode in place instead of
renaming one upper file over one alias.  A persisted object catalog connects a
write through one known name to a read through its sibling.  The publication
path also handles tested upper-created hard-link groups, distinguishes copy-up
from intentional rename-over replacement, and rebases a retained suffix onto a
fresh upper generation.  Bind mounts, external aliases, arbitrary generation
changes, and general multi-object publication remain outside this contract and
fail closed.

\subsection{Durable Commit and Policy}

AgentTX uses anchored include filters to materialize selected frontier paths.
If a later speculative step rewrites one path, AgentTX reconstructs the
frontier version, publishes it, and restores the later upper-layer state.  The
runtime evaluates the persisted policy before WAL preparation or host mutation.

Before publication, the WAL saves affected host paths, the upper layer, the
target frontier, and prior ledger state.  Reload either restores the pre-commit
state or finalizes a durable frontier.  Session metadata uses same-directory
atomic replace followed by file and directory fsync.

The publication path has three observable phases.  \emph{Prepare} records the
frontier and the host values needed for recovery.  \emph{Install} materializes
the selected historical versions under the policy filter.  \emph{Finalize}
records the new frontier and releases obsolete snapshots.  A crash before
finalize leaves the old frontier recoverable; a crash after finalize reloads the
new frontier.  This state machine explains what the WAL contributes without
turning it into a claim of external multi-path atomicity.

A shared allow/deny policy is enforced by the runtime, CLI, coding harness, and
LLM agent.  Policy rules persist across reload.  The WAL provides crash
recoverability, not external all-path atomic visibility: a concurrent observer
can see a prefix while materialization is in progress.

\section{Evaluation}

Our evaluation answers five questions:
\begin{itemize}
  \item[\textbf{RQ1}] Does causal recovery remove invalid descendants while
        retaining independent work (Section~\ref{sec:eval-causal})?
  \item[\textbf{RQ2}] What runtime cost do trajectory isolation and dependency
        capture add (Section~\ref{sec:eval-runtime})?
  \item[\textbf{RQ3}] Which capture, identity, reconstruction, and publication
        mechanisms are necessary (Section~\ref{sec:eval-mechanisms})?
  \item[\textbf{RQ4}] Can a live agent use causal recovery, and how many replay
        tokens does retained work avoid (Section~\ref{sec:eval-agent})?
  \item[\textbf{RQ5}] Do worker failure, reload, long sessions, and concurrency
        preserve the transaction invariants (Section~\ref{sec:eval-robust})?
\end{itemize}

\subsection{Setup and Methodology}

Experiments run on an x86\textsubscript{64} server with an AMD EPYC 7713,
32 online CPUs, 62~GiB of memory, and Linux 5.4.0-216-generic.  The prototype
uses upstream \trycmd, OverlayFS, \texttt{strace}, and Python 3.8.10.  Live-agent
experiments use \texttt{deepseek-v4-flash}.

Every workload starts from a fresh workspace.  Correctness validators inspect
the speculative view and host state before recovery, after recovery, and after
controlled commit.  The fixed comparison uses 50 independent samples per mode;
the causal and token sweeps use three repeats per aggregated configuration.
The live recovery experiment uses three fresh sessions, while the
GitHub-context suite uses one run per task and policy.

We call a run \emph{causal-correct} when the host is clean before publication,
recovery removes the invalid producer and every derived artifact, and the
independent artifact remains visible.  Modes without causal recovery can still
measure execution cost, but they do not satisfy this joint predicate.

We separate baselines by the property they measure.  Bare execution is an
unsafe latency lower bound because it writes to the host immediately.
Per-call \trycmd, session \trycmd, shared \trycmd, shared checkpoints, and
Bubblewrap isolate different execution costs but do not implement causal
recovery.  The no-trace configuration removes read dependencies and serves as
a correctness ablation.  Temporal checkpoint and whole-session abort emulate
coarser recovery over the same trajectory; they are not external-system runs.

\subsection{RQ1: Causal Recovery Semantics}
\label{sec:eval-causal}

We hypothesize that a causal recovery unit can retain later independent work
while removing a failed producer and its descendants.  A temporal recovery
unit should remove the corruption but discard unrelated suffix work.  Removing
dependency capture should instead preserve derived corruption that appears
independent to the ledger.

The sweep executes filesystem effects through the real overlay rather than
simulating graph nodes.  Its 48 aggregated configurations span lengths of
16, 32, and 64; chain, fan-out, and layered DAGs; three fault positions; and
three independent-work ratios.  Causal, temporal, and whole-session recovery
receive identical declared reads, while the fourth mode removes read
dependencies.  Three repeats produce 144 runs, each validated for host
cleanliness, independent retention, and invalid-descendant removal.

Figure~\ref{fig:causal} reports both retention and invalid removal.  Full causal
recovery reaches 100\% on both metrics in every tested configuration.  At
64 calls, temporal recovery removes the invalid work but retains only 41\% of
independent work; whole-session abort retains none.  The no-dependency ablation
retains independent files but removes only 4\% of invalid descendants.

Causal rollback has a p95 latency of 272.7~ms at 64 calls.  The separate
ten-write predicate also succeeds in 50 of 50 full-system runs and zero of
50 runs for every other measured mode.  These experiments validate the
recovery-unit claim on controlled effect DAGs, not arbitrary repository
failures or non-filesystem effects.

\subsection{RQ2: Runtime Cost and Scaling}
\label{sec:eval-runtime}

\subsection{RQ3: Mechanism and Publication Evidence}
\label{sec:eval-mechanisms}

We hypothesize that causal recovery needs all three core mechanisms: typed
effect capture, object-aware reconstruction, and durable publication.  The
mechanism suite combines a 64-call dependency validator, a three-repeat
20-step trace microbenchmark, three policy entry points, and commit failures
on both sides of host installation.  Each test checks the corresponding
ledger, reconstructed view, frontier, and host state.

The 64-call dependency validator injects fault roots at steps $[27,29,30]$.
Full \system identifies all three, removes the faulty formatter and derived
report, and retains the independent documentation, configuration, and repair.
Without read tracing, the ledger identifies only step 27 and leaves the report.
This result connects the 4\% ablation result in RQ1 to a concrete missed edge.

The trace microbenchmark isolates capture cost from tool behavior.  Enabling
tracing raises mean latency from 295.63 to 319.43~ms/step across three repeats,
an increase of 23.80~ms or 8.0\%.  Shell and test commands access more paths,
so this no-op result is not a workload-wide tracing estimate.

Identity tests cover parent-child paths, negative lookups, symlink aliases, and
supported hard-link groups.  With OverlayFS \texttt{index=on}, a lower hard-link
write is visible through its sibling inside the speculative view.  Selective
commit expands a complete pre-existing alias group and publishes both names
through one inode with link count two.  Tested upper-created groups and
intentional rename-over replacement also pass.  Bind mounts, external aliases,
and arbitrary generation changes remain outside the publication contract.

Publication tests apply one deny rule through the direct API, CLI, and a
reloaded session.  All three reject a denied \texttt{*.pem} effect before WAL
preparation, leaving both the frontier and host unchanged.  Failure injection
before and after host installation either restores the prior frontier or
resumes the recorded finalized frontier.  This WAL provides deterministic
recovery, not atomic visibility to an external observer during materialization.

Content-addressed snapshots store 9.1~MB of unique blobs for 100.7~MB of logical
snapshot payload, a 9.0\% ratio.  Regression tests also cover native whiteouts,
mode-000 trees, metadata restoration, and interrupted materialization.  The
storage result does not remove directory traversal, historical snapshot, or
WAL-copy costs.

\section{Discussion and Limitations}

\paragraph{Why not make causal rollback the default?}
The active view uses OverlayFS \texttt{index=on}, which preserves hard-link
visibility within the tested session~\cite{overlayfs}.  Alias-complete
publication covers complete host-visible groups, tested upper-created groups,
and intentional rename-over replacement.  Causal recovery still fails closed
for arbitrary multi-object topology, bind mounts, external aliases, and
unsupported generation changes.

\paragraph{Why trace instead of infer commands?}
Command strings are not a reliable specification of transitive compiler, test,
or script reads.  System-call tracing observes actual accesses but adds
workload-dependent cost and remains Linux-specific.  We therefore use the
strace path for the main correctness and performance claims: in the measured
12-step comparison it costs 25.60 ms/step, versus 61.39 ms/step for the
optional persistent eBPF backend, while both capture the same read and negative
lookup cases in this probe.  The eBPF path remains a replaceable implementation,
not a claim of lower overhead.  Neither tracer removes the need to define alias
and unsupported-syscall semantics or repairs an inode relation already split by
OverlayFS copy-up.

\paragraph{What state is outside the transaction?}
The current \aet covers workspace-local filesystem effects.  Network requests,
emails, package registries, cloud control planes, process memory, and terminal
state may be irreversible or require subsystem-specific compensation.  Systems
that capture full process/session state are complementary, not dominated by
\system.

\paragraph{Is commit atomic?}
The WAL guarantees deterministic recovery of the session and host after an
interrupted commit.  It does not provide kernel-level all-path atomic visibility
to external observers during materialization.  Workloads requiring that
property need a rename-based publication protocol or a transactional substrate.

\paragraph{How strong is the current evidence?}
Deterministic workloads cover up to 256 steps and controlled DAGs up to 64 calls.
Real-agent runs are seeded and use one model.  Several recent external systems
cannot run on the current VM because of FUSE, CRIU, kernel, compiler, or
privilege requirements.  A final submission needs broader repositories,
interleaved statistical runs, and artifact-level comparisons where available.

\section{Related Work}

AgentTX is closest to effect-capturing semisolates, agent-oriented filesystems,
and checkpoint or branch runtimes.  Its distinguishing recovery unit is a
non-contiguous causal subgraph within one speculative trajectory.  We compare
that semantic choice below; without artifact-native measurements, we do not
claim end-to-end superiority.

\paragraph{Effect capture and semisolates.}
\trycmd introduces unprivileged semisolates for opaque commands, including
effect introspection, optional application, and stacking~\cite{try-osdi26}.
\system uses these mechanisms as its execution substrate.  Its focus is the
long-lived trajectory: automatic cross-step dependencies, non-contiguous causal
recovery, frontier materialization, policy persistence, and commit WAL.

\paragraph{Agent-native filesystems and branches.}
YoloFS stages mutations, exposes snapshots, and uses progressive permission to
improve agent/user control~\cite{yolofs}.  Its filesystem mediation and
permission interface are broader than \system's current substrate.  BranchFS
provides nested copy-on-write branch contexts with atomic leaf commit/abort and
first-commit-wins coordination~\cite{branchfs}.  These systems select snapshots
or branches; \system selects a causal subgraph inside one evolving trajectory.

\paragraph{Checkpoint and restore.}
Waypoint combines filesystem deltas with process, memory, shell, and terminal
state for branchable sessions~\cite{waypoint}.  DeltaBox accelerates complete
sandbox checkpoint/rollback using incremental filesystem and process
state~\cite{deltabox}.  Crab observes turn-level effects to avoid checkpoints
that do not contain recovery-relevant state~\cite{crab}.  Their state coverage
or checkpoint efficiency is complementary to \system.  \system instead answers
which non-contiguous filesystem effects to remove after a failure has been
identified.

\paragraph{Process checkpointing and file transactions.}
CRIU and DMTCP preserve complete process/session state for restart, migration,
or debugging~\cite{criu,dmtcp}; their recovery unit is an application image,
not a selected filesystem effect subgraph.  Valor exports POSIX-like file
transactions with kernel logging and locking, while TxFS builds ACID file
transactions on filesystem journaling~\cite{valor,txfs}.  These systems target
atomic publication and crash consistency for explicit transactions.  AgentTX
instead keeps the existing unmodified application interface, infers effects at
opaque tool boundaries, and preserves valid later work after a selective
failure.

\paragraph{Filesystem topology and tracing.}
OverlayFS specifies copy-up, whiteout, and index semantics that determine when
two pathnames still denote one object~\cite{overlayfs}.  System-call tracers
such as \texttt{strace} observe accesses made by arbitrary descendants
~\cite{strace}.  The resulting paths still need hierarchy, descriptor, and alias
normalization.
Our contribution is to connect that observation layer to a causal ledger and a
fail-closed reconstruction policy; we do not claim that a different tracer by
itself solves object identity or selective publication.

\section{Conclusion}

Long-running coding agents need a transaction boundary larger than one command
and a recovery unit smaller than one session.  An Agent Effect Transaction
selects a causal subgraph of versioned effects instead of a temporal suffix.
\system realizes this abstraction with shared speculation, an effect ledger,
selective reconstruction, and a durable commit frontier.  In 144 controlled
runs, it retained all independent work and removed all invalid descendants; at
48 document entries, it also avoided measurable LLM replay.  The result is
limited to supported workspace-local filesystem effects and fail-closed object
identity.
