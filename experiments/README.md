# Current experiment protocol

Terminology / 中英文策略名称：[reference / 术语表](../docs/terminology.md).

Latest repeat evidence: [2026-10-17 reproducibility report](../docs/REPRODUCIBILITY_20261017.md).
The frozen small cohort completed 50 attempts (49 passed, one model task failure);
the 400-case analytical regeneration matched all compared fields. Results remain
protocol validation and do not fill the formal 8400/5410-cell registrations.

The authoritative case definitions, policy semantics, metrics, and paper evidence
boundaries are in [agent.md](../agent.md). The current paper sequence is:

1. Microbenchmark: the same 400 controlled manifests used for Motivation and
   full-system measurement.
2. Real-world workloads: SWE-Bench Lite (300 tasks) and Terminal-Bench
   original-tasks (241 tasks), each with Codex and SWE-agent on Luna max.
3. Breakdown, correctness and interrupted-recovery tests, then other overheads.

The real-world modes are `clean_recovery`, `crash_no_rollback`,
`temporal_checkpoint`, `whole_branch_abort`, and `causal` with compact recovery
context. Fault-enabled modes share the same injection schedule. `ideal_oracle`
is an analytical/microbenchmark bound, not a measured real-world agent result.
Do not mix full and compact causal runs. Keep task failures, missing cells, and
infrastructure errors separate; token comparisons require paired successful
tasks and include replay tokens.

## Running a comparable cohort

Use the `agenttx` Conda environment and preserve the run configuration and
per-cell raw results. The official parallel driver is
`experiments/scripts/run_parallel_official_tasks.py`. `--max-turns` is optional;
omitting it removes the SWE-agent step/model-call count cap. A wall timeout
still applies. For agent-to-agent comparison, an explicit count cap is valid
only when the Codex run uses the same policy. A changed cap, model, prompt,
runner, or verifier requires a new result directory.

SWE-Bench evaluation uses its official Docker verifier. Terminal-Bench needs
the agent itself to work inside each official task image, followed by the
official verifier. The current formal Terminal-Bench driver still runs the
agent on the host; Docker verification alone does not make those rows valid
image-native results. Do not start or resume a formal Terminal-Bench cohort
through that path. The clean native-trace capture path in
`experiments/scripts/capture_clean_native_traces.py` is suitable for the
passive opportunity census, but is not a full recovery-policy driver. For
Terminal-Bench it runs `run-tests.sh` in the same disposable task container
after the agent exits, retaining changes outside the mounted workdir for the
verdict. Verifier timeouts, known download failures, and missing commands are
recorded separately; other dependency errors still need manual review.

The prior Codex five-mode run
`codex_luna_max_realworld_5mode_full_20260930` records 2444 of 2705 expected
cells. Its Terminal-Bench clean arm records only 196 of 241 tasks, including
84 successful rows. The prior SWE-agent five-mode run was stopped after 451
completed rows because it used a workload-derived model-call cap; those rows
and logs have been removed. The replacement SWE-agent runner reconstructs
its native action/observation history from the scripted pre-crash prefix and
projects that history against the post-rollback AgentTX conversation. This is
native-history restoration in a newly initialized SWE-agent object, not a
claim that the scripted prefix was generated by that object's model calls.
Codex instead resumes through a fresh CLI task with a recovery handoff; keep
the two context-recovery mechanisms distinct in comparisons.
The replacement SWE-Bench Lite cohort is running under
`sweagent_luna_max_swe_fair_20261012` (300 tasks, five modes, one repeat,
Luna max, no step/model-call count cap). Its three-mode preflight smoke is in
`sweagent_context_recovery_smoke_v2_20261012`.

## Environment checks

From an activated Conda environment, run
`experiments/scripts/check_experiment_environment.py` on the intended task
set before spending model calls. Terminal-Bench image preparation respects
`services.client.build.context` and its Dockerfile, including the six tasks
with a nested `client/` context. The preflight builds or inspects every
selected Terminal-Bench image, not only tasks with a container-only verifier.
The two QEMU tasks use a dated Debian snapshot when the old Bullseye security
mirror returns 404. The `llm-spec-decoding`, `mnist-learning-fix`,
`reshard-c4-data`, and `word2vec-from-scratch` builds can use
checksum-verified, revision-pinned Hugging Face inputs under
`AGENTTX_TB_ASSET_CACHE` (default:
`~/.cache/agenttx/tb-external-assets`); ordinary image builds run without a
network proxy. Verify each image and its official test runner in Docker; do
not reclassify failed downloads, missing dependencies, or image-build errors
as task failures. Never enable host-wide external writes to work around a
task-image mismatch.

As of 2026-10-12, 239/241 official Terminal-Bench task images are cached.
`fix-git` points to a GitHub repository that returns 404, and
`leelachess0-pytorch-conversion` points to a model file that returns 404.
Neither input is replaced by a different repository or model. Two cached
images (`privilege-escalation`, `unprivileged-headless-pyrender`) start as
non-root users; the current image-native capture runner rejects them because
forcing root would alter the task. The preflight reports these separately from
model failures. This is an image-availability count, not a success rate.

Raw historical measurements remain under `experiments/results/` for audit.
Their former step-by-step experiment plans and DeepSeek-era commands are not
part of the current reproduction protocol.
