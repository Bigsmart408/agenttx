# RQ2 Turn checkpoint 补充实验

补齐真实任务实验中缺少的 Turn checkpoint 对照。运行批次为 `rq2-turn-checkpoint-20261111-r2`，共 1,082 个任务单元，最多八路并行。

| Benchmark | Agent | 任务数 |
|---|---|---:|
| SWE-Bench Lite | SWE-agent | 300 |
| SWE-Bench Lite | Codex | 300 |
| Terminal-Bench | SWE-agent | 241 |
| Terminal-Bench | Codex | 241 |

模型沿用 `gpt-5.6-luna`，reasoning effort 为 `max`，agent 上下文为 `full`。SWE 模型会话时限为 900 秒，TB 为 3,600 秒，TB 最终验收时限为 1,800 秒。故障种子分别为 `20261018` 和 `20261019`。SWE 每任务一次；TB 沿用一次普通失败补跑的设置，各次结果和用量独立保存、累计计费。

Turn checkpoint 直接获得准确的受影响 turn，并撤销这些完整 turn，不做因果扩展。使用注入轨迹原有的 turn 记录，不重新组合调用。当前注入前缀每个工具调用单独记为一个 turn，因此该对照能够保留所有独立笔记；这与 RQ1 中每个 turn 包含多个调用的固定轨迹不同。

执行路径仍为故障注入、恢复、必要的笔记 replay、真实 agent 调用模型完成原任务、官方验收与恢复合约检查。使用已固定的 SWE 任务镜像、TB 任务及验收环境。源码和配置单独冻结，原实验结果保留。

SWE 文件恢复、笔记保留、派生产物清理及 TB 两个 agent 的运行环境预检均通过，预检没有调用外部模型。四个组合各一个真实任务先检查执行和用量有效性；放行后以八路执行全量队列，放行不要求任务解题成功。

结果目录：`/mnt/data/agenttx-runtime/results/rq2-turn-checkpoint-20261111-r2/`。

- `registration.json`：任务规模、策略定义、时限、原实验引用及配置哈希。
- `source-manifest.json`：冻结执行源码的逐文件哈希。
- `preflight/proof.json`：零模型预检结果。
- `cells.json`、`progress.json`：任务状态、当前并发和异常。
- `cells/<benchmark>/<agent>/<task>/attempt-*`：每次执行、用量和验收记录。
- `monitor/latest.json`、`monitor/history.jsonl`：每分钟进度及已完成结果的不可变性核验。

协调服务：`agenttx-rq2-turn-checkpoint-20261111-r2.service`。
监控服务：`agenttx-rq2-turn-checkpoint-20261111-r2-monitor.service`。

`r1` 仅执行过零模型预检。随后修正了调度层的 TB 输出目录和用户身份设置，重新冻结为 `r2` 并重做全部预检；真实模型任务从 `r2` 开始。

## 2026-11-13 持续对照监控

16:56 UTC，正常完成 462 个单元（415 个任务通过、47 个任务失败），基础设施异常 21 个，运行中 8 个，待跑 591 个。异常中 19 个缺少完整 API 用量、2 个为环境异常；其中一个异常单元虽报告任务通过，仍不纳入正常完成和完整成本比较。数据盘余量约 622 GiB。

持续执行以下检查：

1. 原监督服务每分钟核验进度和历史结果哈希。已识别的网关、限流或模型会话超时引起停派时，先检查模型服务和零模型环境，再自动继续 pending。
2. 新增 `agenttx-rq2-comparison-monitor.service` 每分钟更新四个 benchmark/agent 组合与原六类策略的逐任务对照，每五分钟核验冻结执行源码和模型配置。服务已启用，异常退出后 30 秒自动重启。
3. 成本只使用双方成功、所有尝试用量完整、环境配置兼容的任务。失败和补跑成本累计，最终结果按最后一次尝试确定。正在补跑的任务不提前纳入比较。模型、上下文、故障试验种子、环境配置和排除原因均可追溯。

固定对照索引重现了原分析各策略的成功数，包含 6,490 个有结果的历史策略单元、7,334 次尝试。索引生成时核对了原分析输入哈希，并逐项核验现有审计中的结果哈希；SWE-agent 用量从原始 API 日志重新计算。`baseline-manifest.json` 保存固定索引和输入证据的哈希。原实时 SWE 用量审计会定时重生成，因此保存本次读取的哈希，并以已固定的 phase-accounting 和原始 API 记录复算结果为准。

发现并处理两处对照口径问题：

- SWE-agent 的 `total_tokens` 汇总值可能少于 API 逐次返回用量。例如本批 `psf__requests-1963` 汇总为 69,462，API 日志累计为 73,688。新增监控沿用原论文分析的逐次 API 用量口径，不改写实验结果。
- 本批 TB 结果记录了 HF 缓存保留、下载时限和验收下载回退规则，而历史结果包含多种配置。当前已完成 TB 样本与 AgentTX 的严格成本配对为 0，相关配置差异已记入告警；不能据此报告同环境下的成本节省。SWE 对照正常生成。Turn checkpoint 使用 full 上下文，AgentTX 使用 compact，上下文差异在对照中明确保留。

不会修改注册的重试上限：SWE 不自动重试终态单元，TB 只执行已注册的一次普通失败补跑；已终止的基础设施异常不以反复重跑覆盖。已知异常后的自动恢复只续跑待跑队列。未知异常、证据变化、停滞和对照配置不一致写入告警；这些告警不表示对照已经修复，也不会把不兼容样本放入成本比较。

新增入口均在批次的 `comparison-monitor/` 下：

- `latest.json`：最新进度、成功/失败数、逐策略配对、累计 token/耗时、排除原因及配置差异样例。
- `history.jsonl`：每分钟进度和告警记录；`attention.json` 保留最近一次告警快照。
- `baseline.json`、`baseline-manifest.json`：固定的原 RQ2 对照及来源哈希。
- `monitor-registration.json`：监控源码哈希、检查周期和自动续跑范围。

实现为 `scripts/maintenance/watch_rq2_comparisons.py`，新增回归检查覆盖重试累计成本、未知用量、环境变化、故障种子、上下文展示及 API 用量提取。连同原 RQ2 策略和服务故障识别检查，共 16 项通过。
