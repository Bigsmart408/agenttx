# 历史数据能支持的结论

核对日期：2026-10-16（北京时间）。本次读取现有数据，不重跑实验，不改写历史结果。

目前证据最完整的是受控案例中的恢复边界问题，以及 AgentTX 对这些案例的选择性恢复能力。真实任务的成功率、模型 token 和端到端成本比较仍需要处理缺失、环境错误和协议差异。

## 已从原始记录复算的结果

受控集合来自三个 CSV：

- `experiments/results/motivation/controlled_case/controlled_recovery_raw.csv`：100 个案例、600 行。
- `experiments/results/motivation/controlled_case/controlled_position_raw.csv`：90 个案例、540 行。
- `experiments/results/motivation/microbenchmark/motivation_recovery_raw.csv`：210 个案例、1260 行。

合计 400 个注册案例、2400 行，每例都有六个策略，例内策略的 manifest 哈希一致。这些记录的执行类型均为 `ledger_analytical`。下表百分比是案例内比例再对 400 例取平均，不是所有操作合并后计算的比例。

| 策略 | 无效效果移除率均值 | 有效工作丢弃比例均值 | 未清除全部无效效果的案例数 |
| --- | ---: | ---: | ---: |
| 不恢复 | 0% | 0% | 400 |
| 只移除故障根 | 17.03% | 0% | 390 |
| 轮次 checkpoint | 100% | 54.02% | 0 |
| 时间后缀回滚 | 100% | 56.90% | 0 |
| 整分支回滚 | 100% | 100% | 0 |
| 理想精确闭包 | 100% | 0% | 0 |

可支持以下三项受控结论：

1. **安全的粗粒度回滚会丢弃有效工作。** 少回滚看似便宜，但不恢复和仅移除故障根通常无法满足正确性要求。
2. **时间顺序与依赖关系存在结构性错位。** 390/400（97.5%）案例的精确保留集合不是执行前缀；这些目标状态不能由单一历史前缀 checkpoint 表达。这是所测依赖模型内的结论。
3. **固定选一种粗边界不能消除损失。** 按有效工作归因 token 权重比较，轮次 checkpoint 在 139 例更省，时间回滚在 251 例更省，10 例相同。最佳固定选择的总损失仍比逐例选择两者最小值高 10.48%。这里的 token 权重不是实际模型账单；逐例最小值只是诊断参照。

## 实现层面的证据

`experiments/results/external_recovery_motivation400_20260922/external_recovery_raw.csv` 有五个后端、共 2000 行，每个后端 400 个注册案例。400 个注册案例对应 398 个不同的物化 manifest 哈希，不能宣称是 400 种互不重复的物化输入。

| 后端 | 注册案例数 | 无效效果移除率均值 | 有效工作保留率均值 | 精确选择性状态案例数 |
| --- | ---: | ---: | ---: | ---: |
| AgentTX | 400 | 100% | 100% | 400 |
| session_try | 400 | 100% | 0% | 0 |
| branchfs | 400 | 100% | 0% | 0 |
| waypoint | 400 | 100% | 34.11% | 0 |
| yolofs | 400 | 100% | 34.11% | 0 |

这支持：**在当前注册案例和接入方式下，AgentTX 实现了移除无效效果并保留全部有效效果的恢复能力。** 不能由此推出所有工作负载上的正确性保证，也不能把其他后端在这些接入边界下的结果扩大为其全部能力。

该组记录中，AgentTX 平均恢复耗时约 6.00 秒。数据支持保留有效工作的优势；总体性能结论还需把机制开销和后续真实重放成本一起测量。

## 真实轨迹提供什么证据

`experiments/results/motivation/real_trajectory_audit/analysis_full_*_20261008/summary.json` 是历史保存的分析快照，本次没有从受损原轨迹重新生成这些统计。

| 历史快照 | 记录任务数 | 具有跨轮依赖的任务数 | 具有独立写入保留机会的任务数 |
| --- | ---: | ---: | ---: |
| Codex / SWE | 279 | 0 | 19 |
| Codex / Terminal-Bench | 165 | 0 | 58 |
| SWE-agent / SWE | 203 | 181 | 5 |
| SWE-agent / Terminal-Bench | 97 | 73 | 14 |

这支持：**在已观察轨迹和已捕获的工作区路径依赖中，确实存在跨轮依赖与可保留的独立写入；机会随 agent 和任务集合而变化。**

Codex 的轨迹表示采用一个原生执行轮次，跨轮计数为 0 不能解释为没有真实依赖。路径依赖分析未认证间接上下文、别名和未观测效果的独立性，部分轨迹也不完整。因此上述数量是描述性机会，不能换算成已实现的 token 节省或普遍发生率。

## 真实任务实验的当前可用程度

按现有 `run_parallel_official_tasks.merged_rows` 的规则，从分片重新读取；单元键是 suite、task、mode、repeat、harness。完成判定还要求 finished、finish_called、无环境错误，并限制可接受的 error 类型；完成不等于任务成功。

| 实验 | 计划单元 | 有尝试的唯一单元 | 按现有规则完成的单元 |
| --- | ---: | ---: | ---: |
| Codex 五模式，2026-09-30 | 2705 | 2705 | 2444 |
| SWE-agent SWE 五模式，2026-10-12 | 1500 | 1429 | 1237 |

Codex 的 2705 是尝试覆盖数，2444 是筛选后的完成数；不能把两者的差直接叫作数据丢失。SWE-agent 的现存 `merged` 快照有 1233 行，当前分片可选出 1237 个完成单元，确有少量汇总滞后。具体分组统计另存于恢复根目录的 `reports/historical_official_counts.json`。

对 Codex SWE 分片，causal 有 265 个成功任务、whole_branch_abort 有 264 个，二者任务总体均为 300。这个未经配对显著性检验的计数不足以支持普遍提高成功率。SWE-agent causal 记录中有 63 个环境错误，且不同模式的覆盖不同，不能直接比较各模式在已完成行上的成功百分比。

Terminal-Bench 的历史正式路径由主机执行 agent、Docker 执行验收；项目协议已要求 agent 在官方任务镜像内运行。主机权限、依赖和运行边界问题仍会混入结果，不能把当前历史集合称为公平完整的 Terminal-Bench 策略比较。

## 需要补证的结论

- **真实任务更省模型 token、成本或端到端时间：** 需要冻结协议，分别统计失败、环境错误与缺失，并在配对任务上核对完整模型用量和重放用量。
- **普遍提高成功率、优于其他 agent：** 需要相同任务、预算、故障和验收配置，以及配对统计和不确定性分析。
- **完整系统微基准已能独立复核：** `system_microbenchmark/agenttx_causal_luna_max_400x3_20260923` 的汇总仍记录每策略 1200 个单元，但原始 CSV 本轮只救回 36 行。旧汇总可以保留为历史线索，不能作为本次已从完整原始数据复验的结果。

当前登记的实验结果约 72.87 GB、11116 个文件，包含重复导出、日志、轨迹和异常字节；文件体积不是有效实验样本量。恢复后仍有 59 个最初标记的损坏文件未修复，另有空文件和部分恢复记录。详见项目根目录的 `恢复说明.md`。
