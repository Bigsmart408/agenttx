## 原生操作对应

- 固定官方仓库 <https://github.com/binpash/try> 的提交 `833624c956a4f1a990eb3363dafc88b0dc347c16`，保留源码原样；用同一虚拟机的 GCC 编译原生 `try-commit` 和 `try-summary`。源码归档和二进制哈希见 [artifact.json](../review/rq5-try-20261117/artifact.json)。
- 使用 `try -N` 创建并保留原生执行环境。每次检查点正常退出当前环境，保留其 upperdir，再以 `try -N next -L newest:...:oldest` 进入新环境。计时包含退出、挂载叠层和重新进入环境，期间不调用 agent 或模型。
- 工作目录通过独立顶层 bind 别名访问，保存环境仍位于同一底层卷。这样工作目录的 OverlayFS lowerdir 与保存环境相互分离，避免 lowerdir 祖先重叠导致工作负载退到 mergerfs。逐代记录并检查工作目录的 OverlayFS 挂载；原生 try 为其他目录使用其支持的 mergerfs 依赖。
- 工作负载通过原生环境进程的 `/proc/PID/root` 访问同一可写视图。每次切换环境后把新视图路径交回原有 Rust 负载，不替换其文件写入逻辑。
- 最终按最旧到最新的顺序调用原生 `try-commit`，仅发布工作目录的效果。完整流程包含环境初始化、写入、保存和切换环境、原生提交、卸载与清理。
- try 使用上游原生挂载选项，包括 `userxattr,index=off`；OverlayFS、DeltaBox 和 AgentTX 的已有配置及样本保持原样。

## 负载与计量

与现有 RQ5 相同：五次非截断 4 KiB 更新、1 MiB 文件、每次更新后的检查点；块设备写入和包含 syncfs 的更新耗时；100 个 target 与十个覆盖写 seed 文件，各 4 KiB，深度为 1、10、30；二十次独立耗时重复；每个深度十对有/无检查点资源测量。先扣除初始化占用，再计算两种资源增长的差，存储采用 FIEMAP 物理 extent 并集，内存采用独立 cgroup 的 anon、file、kernel 总和，包含全部原生 try 子进程。

独立预检 22 次全部通过。正式批次共 302 次会话，包含 280 次正式测量：40 次局部更新、120 次检查点/完整流程、120 次资源会话。所有正式样本保留；均值和 95% 区间采用与其他 RQ5 对照相同的 10,000 次会话/资源对 bootstrap。历史验证覆盖三代不同文件内容，以及局部更新的六个历史版本；最终发布检查 110 个文件的内容、长度和权限。校验在计时区间之外。

实验挂载和 loop 设备已释放，没有残留原生 try 进程或底层文件系统错误；官方归档中的 83 个文件均与实际源码逐文件哈希一致，11 个测量依赖的哈希也保持不变，见 [环境与清理记录](../review/rq5-try-20261117/environment-and-cleanup.json)。
