# AgentTX 的 YoloFS 移植

## 已验证的恢复路径

实现位于 `agenttx_yolofs/`。它复用原来的 Ledger、文件与上下文依赖联合闭包、verifier 搜索和 ConversationLog，并用 YoloFS 替换文件执行与恢复后端。

工具命令在真实 YoloFS 挂载中执行。strace 返回的挂载路径会转回逻辑文件路径，读访问、文件不存在的判断以及文件修改一起进入依赖图。`call()` 同时绑定调用和返回结果，使上下文依赖能够扩大文件恢复集合。

文件历史由初始对象索引和不可变内容增量组成。每个命令只登记逻辑恢复点及变化对象；原生快照由调用者显式请求。恢复时撤销选中的对象变化，保留当前独立对象，并通过原生文件操作将所需版本装入 YoloFS。原生日志记录恢复后的状态，随后重新挂载与提交能够得到相同的文件内容。

恢复元数据时使用刚创建、已被原生日志引用的暂存 inode，保留文件纳秒时间戳和 xattr。工具执行期间不替换整棵挂载视图，因此恢复流程也不要求每条命令结束时都调用 native snapshot/travel。

verifier 的候选验证使用另一份真正的 YoloFS 挂载。分支共享不变内容副本，并独立安装所需对象；候选验证不会改动父会话。控制器中断后，`load()` 根据恢复 intent 完成文件与上下文的同步。

## 真实挂载验证

最终实现已通过 15 项集成测试。测试涵盖：

- 文件依赖和 agent 上下文依赖联合选择，保留独立调用及其结果；
- 同一原生快照代内，恢复到错误写入之前的有效版本；
- 删除后的不存在路径依赖、多错误根、目录与文件重命名；
- 符号链接、权限、纳秒时间戳、xattr；
- 恢复后的重新挂载、提交、关闭后加载和继续执行；
- 独立 YoloFS 分支中的 verifier 搜索；
- 后台进程保留、超时产生的部分修改恢复、中断后的恢复续接；
- 三代不同内容的原生快照，以及开放写 FD 时的原生快照限制；
- 提交时拒绝工作目录以外的修改，包含共享名称前缀的相邻路径。

测试使用实际 shell 命令和内核文件系统，模型调用数为零。源码见 [integration.py](tests/integration.py)。

## RQ5 的测量范围

RQ5 通过存储 API 测量提交和显式快照，与此前实验使用同样的分层方式。文件依赖捕获和上下文同步由上面的集成测试验证；RQ5 的计时不进入工具追踪、错误定位或按命令保存恢复历史的路径。

负载沿用原始 Rust 程序：每项提交操作处理 10,000 个 4 KiB 文件；快照组先创建 100 个 target 和 10 个 seed，每轮覆盖 10 个 seed，再显式创建快照，深度分别为 1、10、30。

对照包括 AgentTX/YoloFS、原生 YoloFS、AgentTX/OverlayFS、OverlayFS、Ext4，以及原来的 try C、try commit 和 try 完整入口。OverlayFS 两组均开启 metacopy；YoloFS 两组都使用持续打开的控制 FD 和进程内 snapshot ioctl。每项预热一次，再正式测量十次，全部样本保留。

两轮正式实验均为 520/520 通过。首轮的阶段计时与独立 profile 显示，移植版提交前逐文件构建 Path 并检查父路径的代价明显。该检查已改为规范化路径后比较完整目录前缀，保留对工作目录外写入的拒绝；优化后的 15 项回归测试与全部 RQ5 复测均通过。

最终正式测量共 440 个会话，每配置十次；其中 120 个快照会话实际创建了 1,640 次快照。包含预热和历史核验共执行 1,816 次快照调用。所有会话都核验最终文件数量、内容和权限，四个快照对照分别核验三代非零历史内容。

最终提交完整流程均值如下（秒）：

| 操作 | AgentTX/YoloFS | 原生 YoloFS | OverlayFS | Ext4 |
|---|---:|---:|---:|---:|
| 创建 | 0.435 | 0.450 | 0.763 | 0.207 |
| 覆盖 | 0.775 | 0.736 | 1.279 | 0.523 |
| 重命名 | 0.837 | 0.776 | 2.906 | 0.395 |
| 删除 | 0.493 | 0.460 | 0.938 | 0.312 |

相对原生 YoloFS，提交完整流程均值为 0.966–1.079×，快照负载完整流程为 0.967–1.113×。创建和 30 次快照负载的配对区间包含 1，按基本持平解释。相对匹配的 OverlayFS，全部七项提交/快照负载的完整流程均值为 0.288–1.190×。

快照 API 本身仍有 Python 包装开销：移植版均值为 10.7–72.3 微秒/次，原生 YoloFS 为 8.4–41.8 微秒/次。上面的完整流程比值和 API 单次开销分别报告。

完整八组对照、快照 API 与完整流程、分布和配对区间见 [最终 RQ5 报告](results/rq5-final/RESULTS.md)。[集成测试结果](results/integration-v7.json)、[源码与环境最终核验](results/final-verification.json)、[首轮数据](results/rq5-v1/RESULTS.md)和两版源码均已保留。测量期间源码哈希未变化，实验结束后没有遗留的 YoloFS/OverlayFS 挂载或移植实验进程。

## 实现范围

当前提交接口发布全部 active work；部分 frontier 的提交尚未实现。YoloFS 自身未提供的操作（例如创建硬链接）没有在用户态模拟。后台进程保留，进程内存和已有 FD 不进行选择性重建。元数据操作的隔离范围沿用原生 YoloFS。

恢复运行时目前仍扫描工作目录的元数据，并对变化文件保存内容增量。RQ5 的存储 API 数值不包含这部分开销，不能用来代替完整 agent 执行开销的测量。
